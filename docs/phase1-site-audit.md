# Blue Fern public-site architecture audit and Phase 1 boundary

Audit basis: clean source worktree at `29a3dab28b8f079206d8a875e86c2bcaeac66532`, with no Pages checkout and no private operational artifacts copied from the dirty primary worktree.

## Architecture

`src/bluefern_dispatches/generator.py` is the central static builder. `build_site()` writes the root homepage, shared assets, dispatch landing pages, archives, RSS, dated editions, manifests, backups, and selected dispatch mirrors. Gaza has a daily runner (`scripts/run_daily_gaza.py`) that can continue into Pages publishing. Food Line has its own runner (`scripts/run_food_line_dispatch.py`) and private scheduler helpers. Care Line uses the generator plus `care_line_render.py` and the guarded Universal Event Signal Wire path. `scripts/publish_github_pages.py` copies only `output/site/` to a separate Pages checkout; it is an explicit release operation.

The smallest safe redesign boundary is a read-only public-artifact consumer. It derives cards and recent editions from existing public HTML/manifests. Production generator integration is a separately reviewed follow-up because the current `header()`, `footer()`, and `render_root()` helpers are also used by dated pages and archives.

## Gaza write boundary

A normal Gaza run can write dated source/collection context and run manifests under `data/dispatches/gaza/`, public edition/manifests under `output/site/gaza/editions/YYYY-MM-DD/`, the Gaza landing, archive, RSS, and mirrored edition artifacts under `output/dispatches/gaza/`. Explicit operator flags add audio/transcripts/podcast artifacts and Pages synchronization. The root `output/site/index.html` is rewritten by `build_site()` even for scoped generation, while shared assets are copied. The current shell is generated by shared `page()`, `header()`, and `footer()` helpers, not copied navigation. A future shared-shell change must land in those helpers and be regression-tested against Gaza; this prototype does not change them.

No Gaza evidence, editorial content, URL, audio, feed, map, or publication logic was changed.

## Phase 1 information model and design

The private renderer reads only public edition directories and their `edition_manifest.json`, `sources_manifest.json`, and `curation_manifest.json`, plus public edition headings. It exposes dispatch name, status, public URL, archive URL, cadence, latest public date/URL, headline, and counts when present. It never reads review, queue, proposal, inbox, raw payload, or detail roots.

The prototype provides Home/Dispatches/Methodology/About navigation, editorially weighted active cards, recent published developments, archive links, a subdued paused-work list, and project-status/methodology pages. Topics and Places are absent until real destinations exist. No framework or client-side filtering is introduced. Approved repository assets include `assets/dispatches-from-blue-fern-co.png` and `assets/bluefern.png`; the preview uses them with the established palette `#1E3F4F`, `#EFE7DA`, and `#4E6B79`. Focus states, responsive layout, and reduced-motion behavior are included.

## Proposed release boundary

Root/shared: root landing, shared stylesheet/assets, `/methodology/`, `/about/`, and `/dispatches/` generated from new shared helpers.

Generator: refactor `page()`, `header()`, `footer()`, and root/card extraction into shared helpers; add narrow Gaza, Food Line, and Care Line shell regressions. Do not change evidence or edition logic.

Generated public: root landing and shared shell first; dispatch landing/archive regeneration only in a separately declared release. Exclude dated editions, audio/podcast/RSS, maps, Bluesky, private review/proposal files, scheduler definitions, and Pages files from the first release.

This phase stops before public release and creates only source helper, preview script, audit documentation, focused tests, and ignored preview output.
